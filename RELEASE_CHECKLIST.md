# AgriMobi AI — release checklist

## A. Verify (about 10 minutes)
- [ ] `cd frontend && npm install` · `cd ../backend && python -m venv .venv && pip install -r requirements.txt`
- [ ] `bash check_all.sh` passes (golden tests, API/CORS tests, production build)
- [ ] Commit `frontend/package-lock.json` (generated by npm install) so builds are reproducible

## B. Supabase (once)
- [ ] Run `database/001_initial_schema.sql`, then `002_seed_core_knowledge.sql` in the SQL Editor
- [ ] Auth -> enable Email; decide whether email confirmation is required
- [ ] Put URL + anon key in `frontend/.env.local` (never the service-role key)
- [ ] Test: sign up, diagnose, History shows "Synced"; check the row appears in `diagnoses`

## C. Deploy
- [ ] API: `cd backend && python scripts/sync_data.py && docker build -t agrimobi-api .`; host over HTTPS; set `ALLOWED_ORIGINS` to the site URL
- [ ] Frontend: set `VITE_USE_REMOTE_API=true` and `VITE_API_BASE_URL=https://<api>`; `npm run build`; host `dist/` over HTTPS (needed for PWA install + service worker)
- [ ] `curl https://<api>/health` -> ok; browser Network tab shows the POST succeeding (no `blocked:cors`)

## D. Field test (cannot be done by Claude)
- [ ] Install on a real Android phone; use it in airplane mode: diagnose, browse knowledge, view history
- [ ] Re-connect: history syncs; update the site and confirm the phone picks up the new version
- [ ] Android APK: `npm run build:mobile && npx cap add android && npx cap sync` — untested

## E. Content (owner decisions)
- [ ] Verify Zambia/Zimbabwe statistics and sources by URL; get an extension officer to review all 8 core entries
- [ ] Keep dosage-free guidance (current safety decision)

## F. Known limitations to state honestly in any demo
- Rule-based triage, not machine learning; confidence is a heuristic, not a probability
- English input only; 8 core maize problems
- Not a substitute for an extension officer
